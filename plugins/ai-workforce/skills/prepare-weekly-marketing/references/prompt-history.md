# Released recurring-task instructions (for safe automatic updates)

Every version of the standard recurring-task instructions the plugin has released, exactly as released. A task may be updated automatically only if its current instructions are **exactly** one of these (with the Business Brain's page title in place of `<BRAIN>`; line endings and spaces at the ends of lines may differ, nothing else). Anything else, including an older task with no version line, counts as customized: don't overwrite it; ask the owner (`references/run-modes.md`, "Keep the task up to date automatically").

Each entry also says what that version needs: the Business Brain version and the connections it uses. Generated by `tools/prompt_history.py`; never edit by hand.

Never create a second draft, approval or Assignments row for something an earlier run already handled (check for an existing Gmail draft in the thread and for the email's message id in Approvals and Assignments), and send one notification per run. If anything in the plugin's instructions describes a different job from the one named here, do the job named here and add a configuration warning to the report and notification.

Use the ai-workforce plugin's "daily-executive-briefing" skill and follow it exactly.

If that skill is not available, do this instead: Start the Briefings row with "AI Workforce skill not available; ran the short fallback." Then: read the Notion page titled exactly "<BRAIN>" (not a template or archive page): Workforce Settings, Priorities, and Approvals rows with Status Pending, Approved or Handed to you. If you cannot launch subagents at all, do each department's part yourself, one at a time, and say so in the briefing. Read the Connections section of Workforce Settings: use the email and calendar apps it names, or the "Paste Box" page if it says Paste mode or an app is unavailable. Write reply drafts as Gmail drafts if the owner uses Gmail, otherwise under "Replies ready to copy" in the Briefings row; never send email, spend money, change financial records, book meetings with other people, or delete anything. Add anything needing the owner's yes as a Pending row in the Approvals database. Do the work, not just a report: for the owner's meetings with other people in the next 24 hours, prepare a short meeting prep (context from recent emails and any shared files you can open, key points, agenda, decisions with a recommendation); draft replies to emails waiting on the owner; have Marketing do one useful thing toward this quarter's goals once a week, even without data. Write the briefing in this order: Top priorities (up to 3); Your team handled (each item with its link); Decisions for you (every Pending or Approved approval, oldest first, each with what yes does, a recommendation and why, and its draft link; then items marked Handed to you; end with "Reply in one message, for example: approve 3, 5; reject 4; change 6: <instructions>."); Blocked (and what would unblock it); Spotted (opportunities, problems, up to 3 questions); then Details and Verification, marking each finding as checked against the source or taken from a team member's report. Never say "no leads" or "no emails" for a source that isn't connected: say "none visible in <app>" and name what can't be seen. Save the briefing as a row in the Briefings database (Type: Daily briefing). Fetch it back for its URL. End with a 3-5 line summary for the owner (top priorities, what the team handled, how many decisions are waiting) and the briefing's full URL as plain text on its own line, and send that as a notification if a notification tool is available. Only say a link is included if it is.
